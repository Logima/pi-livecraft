# Workspace and sessions

`useWorkspaceSessions` owns workspace selection and the session lists shown by the application. The selected session is represented by the `session` URL query parameter so reloads restore it; browser history changes update the selection as well. It coordinates initial selection, refreshes, creation, reopening, renaming and closing, optimistic naming, pending UI requests, and the local persistence of recent workspaces, completed sessions, and pinned sessions. Recent history preserves Pi's `parentSession` relationship and the sidebar nests related sessions beneath their parent regardless of generated name. This includes delegated agents, forks, and clones because Pi exposes the same structural relationship for each. When the parent contains matching Agent metadata, a generated child uses the Agent tool's short description as its sidebar label and shows its running or finished state without renaming the underlying Pi session. Selecting a child through conversation navigation expands every parent branch needed to reveal it.

`useTabStatus` mirrors all loaded running sessions and finished-unread session counts in the browser title. The title starts with compact counts (`▶2 · ✓3`: running · finished unread). The favicon shows a static ring while running and the unread count (capped at `9+`). It uses no animation timers, so its running indicator remains consistent in background tabs. Completions in the selected session remain unread while the document is hidden and clear when it becomes visible. Focused presentation tests: `test/tab-status.test.ts`.

Keep session-list reconciliation and workspace/session persistence in this controller. `App.tsx` supplies cross-feature callbacks, such as clearing feature state when the workspace changes or preparing an initial composer draft; it should not duplicate the controller's state.

Directory browsing remains in `DirectoryPicker`. Workspace paths accept both `~/...` and Windows `~\...`; completion preserves the separator style the user typed. Pure list and persistence rules live in the neighboring `sidebar-sessions.ts` and `recent-workspaces.ts` modules.

The workspace sidebar presents each known workspace once in deterministic full-path order. The active workspace is marked with `Active`, `aria-current`, a selection bar, and its full path; duplicate directory basenames include their parent path. Recent history remains an MRU input owned by `useWorkspaceSessions`, while workspaces with active, unread, or pinned background sessions are projected into the list even when they are not in that history. Background activity is grouped under its workspace with bounded previews and explicit expansion controls. Current-workspace sessions remain the primary scroll area, with a compact New session action in the section heading.
